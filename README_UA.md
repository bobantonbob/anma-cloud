# ANMA Cloud Integration v0.3.0 — сутності та підключення сайту

## Підключити сайт кодом

Після збереження джерел знову відкрийте «Налаштувати». У полі «Наступний крок» виберіть «Підключення сайту ANMA» → «Надіслати» → «Створити код на 15 хвилин». Передайте код власнику приватно. На сайті він увійде через Google та вкаже назву будинку, Tailscale IP цієї машини й код.

Код одноразовий, перестає діяти через 15 хвилин, після використання, створення іншого коду або перезапуску HA. Він не публікується як сутність і не потрапляє в Recorder. У меню є відкликання ключа читання. Для відновлення створіть код і знову додайте ту саму машину на сайті під тим самим власником — ID будинку та його історія збережуться.

Сайт отримує лише нормалізовані вибрані ANMA-показники. Повного HA-токена не потрібно. Сервер сайту має бути у вашій Tailscale-мережі з доступом до HA на HTTP 8123. Tailscale шифрує мережевий транспорт; обмежте firewall/ACL доступом сервера, не відкривайте endpoint публічно. Код не підключає машину до Tailscale автоматично.

В архіві є новий файл `pairing.py`; копіюйте всю папку компонента. Наявні прив’язки не видаляйте. API та параметри перевірено локальними тестами; повний запуск у вашому HA ще потребує встановлення ZIP.

## Оформлення ANMA та стан системи

Над полями одразу показується підсумок за вибраними джерелами: генерація сонця, споживання будинку, заряд/розряд батареї з SOC та імпорт/експорт мережі. Враховується інверсія знака. За відсутності джерела показано «немає даних». Відсутність мережі визначається тільки окремим датчиком доступності; нульовий обмін не означає відключення.

Підсумок оновлюється під час відкриття, надсилання форми та команди оновлення. Це знімок стану. Після зміни вибору натисніть «Надіслати», щоб побачити новий підсумок. У новій інсталяції спочатку потрібно вибрати джерела.

Іконки створені саме з наданого `staticfiles/img/favicon.ico`. Заголовок містить ANMA Cloud; кольори контролів визначаються темою Home Assistant. Пакет не змінює глобальну тему HA. Зображення бренду показуються в місцях, передбачених інтерфейсом HA; довільний CSS у стандартний діалог не додається.

Для v0.2.1 додані три тести напрямків потоків, відсутніх даних і суперечливого статусу мережі: загалом 16 локальних тестів.

## Що нового

- У полі введіть `bat`, частину назви або `entity_id`: Home Assistant запропонує відповідні наявні джерела.
- Кожен варіант показує дружню назву, поточний стан, одиниці та ID. Наприклад: `Battery power · 0.743 kW · sensor.battery_power`.
- Для потужності пропонуються W/kW, для SOC — %, для енергії — Wh/kWh. Вихідні датчики самої ANMA виключені, щоб уникнути циклів.
- Перед збереженням є перегляд джерела та результату після перетворення одиниць і знака. Значення беруться зі станів HA під час відкриття/оновлення форми, не змінюються автоматично у відкритому списку.
- «Оновити значення у списках» + «Надіслати» перечитує стани зі збереженням чернетки. На екрані перегляду є окрема кнопка оновлення.
- «Не використовувати» прибирає окрему прив’язку. Наявні, але тимчасово недоступні джерела зберігаються.
- Додана помаранчева іконка ANMA для світлої й темної тем у `brand/`. Локальні іконки підтримуються починаючи з HA 2026.3; на вашому HA 2026.9.1 ця можливість є.

## Оновлення існуючої інтеграції

1. Збережіть копію наявної папки `/config/custom_components/anma_cloud`.
2. Скопіюйте папку `custom_components/anma_cloud` з цього ZIP на її місце, включно з `mapping.py`, `translations/` і `brand/`.
3. Перезапустіть Home Assistant. Не видаляйте інтеграцію зі списку «Пристрої та служби».
4. Відкрийте **Налаштування → Пристрої та служби → ANMA Cloud → Налаштувати**.
5. Виберіть джерела пошуком, натисніть «Надіслати», перевірте результат і натисніть «Зберегти прив’язки».

Домен `anma_cloud`, installation_id, unique_id сутностей і ключі параметрів збережені. Перемикачі інверсії не змінюються автоматично. Оригінальний ZIP v0.1 та працююча інсталяція HA цією збіркою не змінювалися.

Для нового підключення кодом напрямки визначає інтеграція: сайт не застосовує повторну інверсію. Для старого підключення через `.env` параметр `HA_BATTERY_SIGN` залишається чинним — перевірте, щоб інверсія не дублювалась.

Інтеграція працює **лише для читання**. Вибрані джерела залишаються в HA, а інтеграція створює стандартизовані датчики. Налаштування з’єднання Cloud Lite з HA виконується окремо.

## Встановлення на Home Assistant OS

1. Створи резервну копію конфігурації HA.
2. Через **File Editor**, **Studio Code Server** або **Samba** відкрий каталог `/config`.
3. Якщо немає `/config/custom_components`, створи його.
4. Скопіюй папку `custom_components/anma_cloud` з архіву в `/config/custom_components/anma_cloud`. Важливо, щоб безпосередньо в цій папці лежали `manifest.json`, `config_flow.py`, `sensor.py`, `binary_sensor.py` та інші файли.
5. Перезавантаж Home Assistant: **Налаштування → Система → Перезапустити Home Assistant**.
6. **Налаштування → Пристрої та служби → Додати інтеграцію → ANMA Cloud**.
7. Після додавання відкрий **ANMA Cloud → Налаштувати**. У пошукових полях вибери відповідні датчики. Пусті поля залишай пустими.
8. Натисни «Надіслати», перевір результат і вибери «Зберегти прив’язки»; сутності оновлюватимуться при зміні вихідних датчиків.
9. Перевір **Інструменти розробника → Стани**, фільтр `anma_`.

## Рекомендоване початкове зіставлення для Deye

| ANMA поле | Приклад джерела |
| --- | --- |
| PV power | `sensor.inverter_pv_power` |
| Load power | `sensor.inverter_load_power` |
| Battery SOC | `sensor.inverter_battery` (якщо відображає %, перевір у Стани) |
| Grid power | вибрати фактичний датчик імпорту/експорту зі знаком |
| Battery power | вибрати фактичний датчик із напрямком заряд/розряд |

**Не вгадуй відсутні entity_id.** Якщо в тебе інша схема, вибирай у формі реальні джерела.

## Знаки

- `grid_power`: **+** імпорт, **−** експорт.
- `battery_power`: **+** заряд, **−** розряд.
- У параметрах інтеграції є перемикачі інверсії знака для обох датчиків.

## Одиниці вимірювання

Інтеграція підтримує перетворення `kW → W` і `Wh → kWh`, якщо у джерела правильний атрибут `unit_of_measurement`. Для невідомих одиниць показник переходить у `unavailable`, замість того щоб мовчки відобразити хибне число.

## Імена сутностей

Інтеграція пропонує назви `sensor.anma_pv_power`, `sensor.anma_load_power`, `sensor.anma_battery_soc` тощо. Home Assistant може додати суфікс `_2` при конфлікті назв. Перевір фактичні `entity_id` у HA та за потреби зміни через налаштування сутності. Це не видаляє та не переписує оригінальні датчики.

## Перевірка цієї збірки

Пройдено 13 локальних тестів: пошук і фільтрація, перевірка джерел, перетворення одиниць і знака, збереження чернетки, оновлення, очищення прив’язок та переклади. Межі API Home Assistant у цих тестах замінено тестовими об’єктами; це не повний запуск інтеграції всередині HA. Також перевірено синтаксис Python та добір джерел на фактичних станах підключеного HA без їх зміни.

Після встановлення потрібно перевірити форму в інтерфейсі HA: пошук `bat`, відображення поточного значення, перегляд і збереження. Цей ZIP ще не встановлено на працюючий Home Assistant.

Іконки використовують стандартну папку локального брендингу: [документація Home Assistant](https://contributors.home-assistant.io/core/integrations/file-structure/). Публікація репозиторію та налаштування HACS до цієї збірки не входять.
